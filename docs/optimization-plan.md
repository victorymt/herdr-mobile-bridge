## 第三阶段：手机端任务与回复流程

用户视角审查发现：首页大面积展示电脑聚焦状态，但输出与控制可能属于另一个任务；同名智能体难以区分；收到通知后要越过多个输入表单才能看到上下文。

实施顺序与结果：

1. 合并顶部摘要与任务选择区，当前任务在摘要、下拉框、输出、回复和发送确认中使用一致的工作区与窗格标识。电脑显示作为辅助信息；“在电脑中打开”只改变电脑画面，保留手机目标。
2. 首页增加任务列表，优先排列需要介入的任务；首次无选择时优先选中需要处理的任务，后续状态更新保留用户选择。点击需要介入的任务进入待处理页，其他任务进入输出页，均不触发电脑聚焦。
3. 待处理页按“任务与状态 → 最近输出 → 回复”排列。“输入并回车”明确发送文字与 Enter；仅输入文字不会自动回车。新任务和额外终端按键默认折叠，保留发送任务和中断按键的确认。
4. 删除重复快捷入口和“读取”按钮，保留统一的输出刷新；连接详情折叠。压缩手机顶部区域，关键辅助文字至少 12px，正文、输入与输出使用 16px，交互按钮至少 44px。
5. 切换任务时清除不属于新任务的输出并作废旧读取；迟到的输出响应不再改变用户正在查看的页面。区分尚未读取、空输出和读取失败的预览提示。
6. App Shell 缓存升级为 `herdr-mobile-v30`。

验证：新增 14 项 DOM 行为回归，全量测试 223/223 通过；20 个生产 JS 文件的语法检查与 `git diff --check` 通过。新增回归也覆盖固定导航仅纠正实际遮挡、不对折叠详情或屏幕外任务自动滚动。浏览器使用隔离的 Bridge 与假 Herdr 客户端，避免影响真实会话。

- 浏览器窄屏实测发现长工作区与窗格标识会撑宽任务摘要及电脑显示列表；两处补上断词换行，320px 下复验页面宽度保持 320px。手机通知设置弹层改为相对顶部栏定位，也已验证未越界。
